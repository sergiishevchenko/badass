# BADASS — Инструкция с нуля: от пустой Ubuntu до работающей сети в GNS3

Этот файл написан для человека, который **никогда не открывал GNS3**.

Ты не обязан заранее знать, что такое «шаблон», «адаптер» или «portable project».  
Всё объясняется в момент, когда это впервые появляется на экране.

---

Тебе нужны **две программы** на одной Ubuntu-машине:

| Программа | Простыми словами |
|-----------|------------------|
| **Docker** | Фабрика «мини-компьютеров» (контейнеров). Мы заранее собираем два типа: обычный хост и роутер. |
| **GNS3** | Рисовалка сети. Ты кладёшь на белый лист иконки устройств, соединяешь их линиями (кабелями), жмёшь Start — и можешь зайти внутрь каждого устройства в чёрное окно терминала. |

Порядок всегда такой:

```text
1) Установить Docker
2) Установить GNS3
3) Собрать два Docker-образа (dmiasnik-host и dmiasnik-router)
4) Открыть GNS3 и ОДИН РАЗ создать «шаблоны» этих образов
5) Нарисовать топологию Part 1 → Start → вписать IP → ping
6) То же для Part 2 и Part 3
7) File → Export portable project (с образами) — это сдача
```

Пока шаг 3 не сделан, в GNS3 в списке образов будет пусто. Это нормально — просто рано открыл редактор.

---

## 0. Какая машина нужна

Нужна **Ubuntu 22.04 или 24.04**, архитектура **x86_64** (обычная Intel/AMD VM школы).

Минимум: 4 CPU, 8 GB RAM, 40 GB диск.

> MacBook на чипе M1/M2/M3: путь «VirtualBox с Ubuntu на Mac → внутри ещё GNS3» обычно **ломается**. Этот гайд — про Ubuntu x86 (школьная VM / удалённый Linux). На Apple Silicon нужна другая схема.

Проверка в терминале Ubuntu:

```bash
whoami
free -h
nproc
ls /dev/kvm
```

Файл `/dev/kvm` желателен (ускорение виртуализации). Если его нет — Docker-часть BADASS часто всё равно работает, но предупреждение имей в виду.

# ЧАСТЬ A. Подготовка системы (терминал)

Открой терминал Ubuntu (`Ctrl+Alt+T`).

## A1. Установка Docker

Скопируй и выполни **блоками**. После каждого блока читай, что написано ниже.

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y ca-certificates curl gnupg lsb-release
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

Смысл последней строки: твоему пользователю разрешили пользоваться Docker без `sudo`.

**Обязательно** либо выйди из сессии и зайди снова, либо выполни:

```bash
newgrp docker
```

Проверка — должна напечатать Hello from Docker:

```bash
docker version
docker run --rm hello-world
```

Если видишь `permission denied` про `docker.sock` — ты всё ещё не в группе `docker`. Сделай logout/login и повтори.

## A2. Установка GNS3

```bash
sudo apt install -y software-properties-common
sudo add-apt-repository ppa:gns3/ppa
sudo apt update
sudo apt install -y gns3-gui gns3-server
```

На вопросы установщика (wireshark, ubridge и т.п.) обычно можно отвечать **Yes**, чтобы обычный пользователь мог захватывать пакеты / использовать ubridge.

Дополнительно:

```bash
sudo apt install -y \
  python3-pip \
  python3-pyqt5 \
  python3-pyqt5.qtsvg \
  python3-pyqt5.qtwebsockets \
  qemu-kvm \
  qemu-utils \
  libvirt-daemon-system \
  libvirt-clients \
  bridge-utils \
  wireshark
```

Группы:

```bash
sudo usermod -aG ubridge,libvirt,kvm,wireshark,docker $USER
sudo reboot
```

После перезагрузки снова открой терминал:

```bash
groups
gns3 --version
docker info
```

В `groups` должны мелькать `docker`, желательно `ubridge`, `wireshark`.

## A3. Включить IP forwarding

```bash
sudo sysctl -w net.ipv4.ip_forward=1
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-ipforward.conf
sudo sysctl --system
sysctl net.ipv4.ip_forward
```

Последняя команда должна показать `net.ipv4.ip_forward = 1`.

## A4. Сборка двух образов проекта

Перейди в папку репозитория (путь поправь под себя):

```bash
cd ~/badass
```

Собери образы (это займёт время; нужен интернет):

```bash
docker build -t dmiasnik-host -f P1/Dockerfile.host P1/
docker build -t dmiasnik-router -f P1/Dockerfile.router P1/
```

Проверка, что образы есть:

```bash
docker images | grep dmiasnik
```

Ты должен увидеть две строки: `dmiasnik-host` и `dmiasnik-router`.

Быстрая проверка host:

```bash
docker run --rm dmiasnik-host sh -c "busybox | head -1; which ip; which ping; which tcpdump"
```

Быстрая проверка router (демоны FRR):

```bash
docker run --rm -d --name test-router --privileged dmiasnik-router
sleep 4
docker exec test-router ps aux | grep -E "zebra|bgpd|ospfd|isisd|watchfrr"
docker exec test-router vtysh -c "show version"
docker exec test-router which brctl
docker stop test-router
```

Если `zebra` / `bgpd` / `ospfd` / `isisd` не видны — **стоп**. Чини образ (`P1/daemons`, Dockerfile) до GNS3. Иначе будешь отлаживать не то.

# ЧАСТЬ B. Первый запуск GNS3 (ещё без нашей сети)

## B1. Как открыть программу

Вариант 1 — в терминале:

```bash
gns3
```

Вариант 2 — меню приложений Ubuntu: поиск **GNS3** → клик по иконке.

Подожди несколько секунд. Откроется окно программы.

## B2. Мастер первого запуска (Setup Wizard)

При **первом** запуске часто вылезает окно **Setup Wizard**.

Тебе нужно понять одну мысль:

> Для BADASS всё крутится **на этом же компьютере** (local).  
> Отдельная «GNS3 VM» из VirtualBox **не нужна**.

Типичные экраны (формулировки чуть отличаются по версиям):

### Экран про способ запуска

Если видишь варианты вроде:

- *Run appliances on my local computer*
- *Run appliances on a remote server*
- *Run appliances on the GNS3 VM*

→ выбери **local computer** / локальный компьютер.

### Экран про GNS3 VM

Если предлагает скачать / настроить GNS3 VM (VirtualBox/VMware) → **Skip** / **Don't use** / закрой этот путь. Нам достаточно Docker на этой Ubuntu.

### Дальше

Жми **Next** / **Finish**, пока wizard не закроется.

Если wizard не появился — тоже нормально. Идём в настройки вручную.

## B3. Проверить, что «мозг» GNS3 жив (local server)

GNS3 состоит из двух частей:

- **GUI** — то окно, которое ты видишь;
- **Server** — фоновый процесс, который реально запускает Docker-контейнеры.

Без сервера холст красивый, но Start не работает.

Сделай так:

1. В **верхнем меню** окна GNS3 кликни **Edit**.
2. В выпадающем списке кликни **Preferences…** (Настройки).
3. Слева появится **дерево разделов**.
4. Найди пункт **Server** и раскрой его (треугольник / клик).
5. Кликни **Local server**.

Справа проверь примерно:

| Поле | Ожидание |
|------|----------|
| Host | `localhost` или `127.0.0.1` |
| Port | `3080` |

Нажми кнопку **Apply** внизу окна Preferences.  
Потом **OK**.

Посмотри **самый низ** главного окна GNS3 (тонкая статус-строка).  
Должно быть что-то вроде connected / local server, **без красной ошибки** `Can't connect to server`.

Если ошибка есть:

```bash
# в отдельном терминале
gns3
```

или перезагрузи Ubuntu и открой GNS3 снова.

## B4. Экскурсия по главному окну (запомни навсегда)

После закрытия Preferences ты видишь roughly это:

```text
┌─ File   Edit   View   Control   Tools   Help ──────────────────────┐
│  ▶   ■   ⏸   ⟳    🖥     🔗                                      │
│ Start Stop     Console  Add link   ← ЭТО ГЛАВНЫЕ КНОПКИ           │
├────────────┬─────────────────────────────────────┬─────────────────┤
│            │                                     │                 │
│  СПИСОК    │         БЕЛЫЙ ХОЛСТ                 │  Topology       │
│  УСТРОЙСТВ │         (пока пустой)               │  Summary        │
│  СЛЕВА     │                                     │  (список узлов  │
│            │     сюда будем таскать              │   проекта)      │
│  иконки    │     иконки и рисовать               │                 │
│  шаблонов  │     кабели                          │                 │
│            │                                     │                 │
└────────────┴─────────────────────────────────────┴─────────────────┘
│ внизу: статус сервера                                              │
└────────────────────────────────────────────────────────────────────┘
```

### Левая колонка — «склад заготовок»

Там лежат **типы** устройств (роутеры Cisco, VPCS, облака…).  
Пока наших `dmiasnik-host` / `dmiasnik-router` там **нет** — мы их ещё не добавили. Это следующий большой шаг.

Если левой колонки не видно:

**View → Docks → All devices**  
(или похожий пункт Show / Browse all devices).

### Центр — холст

Сюда кладут устройства конкретной сети (проекта). Пустой холст = сети ещё нет.

### Справа — Topology Summary

Список устройств **текущего** проекта. Удобно кликать правой кнопкой.

### Верхние кнопки (самое нужное)

| Кнопка | Что делает |
|--------|------------|
| **▶ Start** | Запускает устройства (Docker-контейнеры начинают жить) |
| **■ Stop** | Останавливает |
| **Console** | Открывает чёрное окно «ты внутри устройства» |
| **Add a link** (кабель) | Режим «сейчас я соединяю два порта проводом» |

Пока **ничего не запускай**. Сначала создадим шаблоны.

# ЧАСТЬ C. Один раз создать шаблоны Docker (самое важное в GNS3)

## C0. Что такое «шаблон» простыми словами

**Шаблон** = карточка в левой панели:  
«когда тащат эту иконку на холст — подними контейнер из образа X, дай ему N сетевых розеток».

Ты создаёшь шаблон **один раз**.  
Потом в Part 1 / 2 / 3 просто таскаешь иконки мышкой.

Без шаблонов рисовать нашу сеть **нельзя** — нечего перетаскивать.

## C1. Открыть список Docker-шаблонов

1. Меню сверху: **Edit**.
2. **Preferences…**.
3. В левом дереве найди раздел **Docker**.
4. Кликни строку **Docker containers** (не просто Docker, а именно containers).

Справа:

- таблица шаблонов (сейчас пустая или почти пустая);
- внизу кнопки **New** / **Edit** / **Delete**.

5. Нажми **New**.

Откроется мастер из нескольких экранов с кнопками **Back / Next / Cancel / Finish**.

## C2. Шаблон хоста — экран за экраном

### Экран «Server»

Спросит, где запускать контейнер.

→ Выбери **local** (локальный сервер).  
→ **Next**.

### Экран «Docker image»

Появится список Docker-образов, которые GNS3 видит на этой машине.

→ В списке найди и выдели **`dmiasnik-host`**.  
→ **Next**.

**Если списка нет или нет `dmiasnik-host`:**

1. Нажми **Cancel**.
2. Закрой Preferences (**Cancel** / **OK**).
3. В терминале проверь:

```bash
docker images | grep dmiasnik
```

4. Если образов нет — вернись к разделу **A4** и собери их.
5. Полностью закрой GNS3 и открой снова (`gns3`).
6. Снова **Edit → Preferences → Docker containers → New**.

GNS3 читает список образов при старте / открытии wizard. Без перезапуска часто «не видит» свежий build.

### Экран «Name»

Имя **шаблона** (как будет подписана иконка слева).

→ Впиши: `dmiasnik-host`  
→ **Next**.

Это ещё **не** имя устройства на схеме. На схеме потом переименуем в `_dmiasnik-1_host`.

### Экран «Adapters» (сетевые карты)

Спросит, сколько сетевых интерфейсов дать контейнеру.

→ Поставь **`1`**.  
→ **Next**.

Внутри Linux это будет один интерфейс `eth0` — одной «сетевой розетки» хосту хватит.

### Экран «Start command»

Команда, с которой стартует контейнер.

→ **Оставь поле ПУСТЫМ**.  
→ **Next**.

Почему пустым: в нашем Dockerfile уже прописано `CMD ["tail", "-f", "/dev/null"]` — процесс, который просто живёт вечно. Если сюда вписать ерунду, контейнер может сразу умереть, и консоль мигнёт и закроется.

### Экран «Console type»

Как GNS3 открывает «терминал внутри устройства».

→ Если в списке есть **`telnet`** — можно оставить **telnet** (часто стоит по умолчанию, для Docker это нормально).  
→ Если есть отдельный пункт вроде **docker** — тоже ок.  
→ **Не** выбирай VNC / HTTP.

→ **Next**.

### Экран «Environment variables»

Переменные окружения.

→ **Ничего не пиши**.  
→ **Finish** (или Next → Finish).

Ты вернулся в список Docker containers. Там должна появиться строка **`dmiasnik-host`**.

**Не закрывай Preferences.** Сразу делаем второй шаблон.

## C3. Шаблон роутера — тот же мастер

Снова кнопка **New**.

| Экран | Что выбрать / вписать |
|-------|------------------------|
| Server | **local** |
| Image | **`dmiasnik-router`** |
| Name | **`dmiasnik-router`** |
| Adapters | **`4`** ← важно |
| Start command | **пусто** |
| Console type | **telnet** (или docker, если есть) |
| Environment | пусто → **Finish** |

### Зачем роутеру 4 adapters

Внутри контейнера adapters становятся `eth0`, `eth1`, `eth2`, `eth3`.

| Часть проекта | Сколько портов реально нужно |
|---------------|------------------------------|
| Part 1 | 1 |
| Part 2 | 2 (к соседу-роутеру + к хосту) |
| Part 3 RR | 3 (три линка к VTEP) |
| Part 3 VTEP | 2 |

Лишние порты просто **не подключаешь кабелем**. Это нормально.  
А вот если поставить 1 adapter, в Part 3 у Route Reflector **не будет** eth1/eth2 — кабель воткнуть некуда.

В списке теперь две строки: `dmiasnik-host` и `dmiasnik-router`.

Нажми **Apply**, затем **OK** — Preferences закроется.

## C4. Убедиться, что иконки появились слева

В левой панели устройств найди:

- `dmiasnik-host`
- `dmiasnik-router`

Где искать:

- вкладка / фильтр **All devices**;
- или категория **End devices** / **Docker containers** / гости.

Если не видно:

1. **Edit → Preferences → Docker containers** — шаблоны на месте?
2. Закрой и открой GNS3.
3. **View** — включи панель устройств заново.

Поздравляю: склад заготовок готов. Дальше — первая настоящая сеть.

# ЧАСТЬ D. Part 1 с нуля — первая работающая сеть

Цель: два устройства, один кабель, `ping` проходит.  
Если здесь застрял — **не иди в Part 2**.

## D1. Что должно получиться

```text
   _dmiasnik-1_host                _dmiasnik-2
   (это host)                      (это router)
        eth0 ──────────────────────── eth0
```

Как обычный патч-корд между ноутбуком и роутером.

## D2. Создать пустой проект

1. Меню **File → New blank project**  
   (или на стартовом экране кнопка создать новый проект).
2. Появится окошко:
   - **Name:** впиши `P1`
   - **Location:** папка, куда GNS3 сложит файлы проекта (можно оставить по умолчанию)
3. Нажми **OK**.

Холст пустой. Справа Topology Summary пустой. Это нормально.

Сохраняйся часто: **File → Save** (или Ctrl+S).

## D3. Положить host на холст

1. В **левой** панели найди иконку **`dmiasnik-host`**.
2. Наведи мышь на иконку.
3. **Зажми левую кнопку** мыши.
4. Не отпуская, **тащи** курсор на белый холст.
5. **Отпусти** кнопку.

На холсте появится устройство. Имя будет вроде `dmiasnik-host-1` — пока не страшно.

Если случайно положил два — лишний удали: кликни по нему → клавиша **Delete**.

## D4. Положить router на холст

То же самое с иконкой **`dmiasnik-router`**.

Положи его **справа** от host — так нагляднее.

Сейчас на холсте две иконки, **кабеля между ними ещё нет**.

## D5. Переименовать устройства (требование логина)

Имена на схеме должны содержать твой логин.

### Host

1. Наведи мышь на иконку host на холсте.
2. Нажми **правую** кнопку мыши.
3. В меню найди пункт вроде:
   - **Change hostname**
   - или **Change name**
   - или **Configure…** → поле Name
4. Сотри старое имя.
5. Впиши точно: `_dmiasnik-1_host`
6. Подтверди **OK**.

Подпись под иконкой должна смениться.

### Router

Правый клик → Change hostname → впиши `_dmiasnik-2` → OK.

> Имя на холсте и имя Docker-образа — разные вещи.  
> Образ по-прежнему `dmiasnik-router`. На схеме мы только подписали узел.

## D6. Соединить кабелем eth0 ↔ eth0

Сейчас самое важное место для новичка.

1. На **верхней панели** инструментов найди иконку кабеля / штекера (**Add a link**).
2. **Кликни по ней один раз**.  
   Курсор обычно меняется — программа ждёт, к чему «воткнуть» провод.
3. **Левой кнопкой кликни по иконке `_dmiasnik-1_host`** на холсте.
4. Всплывёт маленькое меню портов. Для host там обычно один пункт, например:
   - `Ethernet0`
   - или `eth0`
   - или `Adapter 0`
5. Кликни этот единственный порт.
6. Теперь **кликни по иконке `_dmiasnik-2`**.
7. Снова меню портов. У роутера портов несколько (мы ставили 4). Выбери **первый**:
   - `Ethernet0` / `Adapter 0`
8. Между устройствами появится **линия**. Это кабель.

Выйди из режима кабеля:

- клавиша **Esc**,  
- или снова клик по инструменту выделения / Add a link.

### Как читать имена портов

| В меню GNS3 при соединении | Внутри контейнера в Linux |
|----------------------------|---------------------------|
| Ethernet0 / Adapter 0 | `eth0` |
| Ethernet1 / Adapter 1 | `eth1` |
| Ethernet2 / Adapter 2 | `eth2` |

В Part 1 нужны только нулевые порты с обеих сторон.

### Если соединил не те порты

1. Кликни по **линии** кабеля (она выделится).
2. Клавиша **Delete**.
3. Снова Add a link и соедини правильно.

## D7. Запустить оба устройства

1. На верхней панели нажми зелёную **▶** (**Start/Resume all devices**).  
   Либо меню **Control → Start/Resume all devices**.
2. Подожди **3–10 секунд**.
3. Иконки обычно меняют вид (становятся «живыми» / зеленоватыми — зависит от темы).

Проверка снаружи в терминале Ubuntu:

```bash
docker ps
```

Должны появиться новые контейнеры (имена длинные, с id). Если `docker ps` пустой — Start не сработал или контейнеры сразу упали.

## D8. Открыть консоль host и прописать IP

**Консоль** = чёрное окно, где ты «сидишь внутри» устройства.

Как открыть:

**Способ 1:** двойной клик по иконке `_dmiasnik-1_host`.  
**Способ 2:** один клик по иконке → кнопка **Console** на панели.  
**Способ 3:** правый клик по иконке → **Console**.

Должен появиться терминал с приглашением вроде `#` или `/ #`.

Если окно мигнуло и сразу закрылось — контейнер мёртв. Смотри раздел «Боли новичков» в конце.

В консоли host **аккуратно** введи (можно копипаст, но **без** строки `#!/bin/sh`):

```bash
ip addr add 10.1.1.1/24 dev eth0
ip link set eth0 up
```

После каждой строки Enter.

Проверка:

```bash
ip addr show eth0
```

Должен быть виден `10.1.1.1/24`. В строке состояния интерфейса — `UP` / `LOWER_UP`.

Что означают команды (коротко):

- первая — повесить IP и маску `/24` на сетевую карту eth0;
- вторая — «включить» карту (как поднять рычажок порта).

## D9. Открыть консоль router и прописать IP

Открой консоль `_dmiasnik-2` тем же способом.

```bash
ip addr add 10.1.1.2/24 dev eth0
ip link set eth0 up
ip addr show eth0
```

## D10. Проверить ping — момент истины

В консоли **host**:

```bash
ping -c 3 10.1.1.2
```

Ожидание: три ответа, 0% packet loss.

В консоли **router**:

```bash
ping -c 3 10.1.1.1
ps aux | grep -E "zebra|bgpd|ospfd|isisd"
vtysh -c "show version"
```

Должны быть видны процессы демонов и ответ `vtysh`.

### Если ping не идёт — чеклист новичка

1. Оба устройства **Start** (не Stop)?
2. Кабель на схеме есть? Ethernet0 ↔ Ethernet0?
3. Команды `ip link set eth0 up` выполнены на **обоих**?
4. Адреса правда `10.1.1.1` и `10.1.1.2` с `/24`?
5. Не перепутал консоли (IP host повесил на router)?
6. `docker ps` показывает контейнеры?

Когда ping прошёл — Part 1 по сути **работает**. Дальше экспорт (раздел G) можно сделать сразу или после Part 2/3.

**File → Save.**

# ЧАСТЬ E. Part 2 — те же клики, больше коробок

Если Part 1 не пингуется — сюда не ходи.

## E1. Картинка в голове

```text
host1 ---- router1 ======== router2 ---- host2
 eth0       eth1  eth0     eth0  eth1      eth0
              \____ underlay ____/
```

Два «компьютера» по краям, два «роутера» в середине.  
Между роутерами — кабель **eth0–eth0**.  
Каждый хост воткнут в **eth1 своего** роутера (не в eth0!).

Имена для static-варианта:

- `_dmiasnik-1_host`
- `_dmiasnik-1_s`
- `_dmiasnik-2_s`
- `_dmiasnik-2_host`

## E2. Новый проект

1. **File → New blank project**
2. Name: `P2` (или `P2-static`)
3. OK

Старый P1 можно закрыть / оставить — не смешивай всё на одном холсте.

## E3. Натащить 4 устройства

1. Перетащи **два** `dmiasnik-router`.
2. Перетащи **два** `dmiasnik-host`.
3. Разложи **в одну линию слева направо**:

```text
[host]    [router]    [router]    [host]
```

Так меньше шансов перепутать кабели.

## E4. Переименовать

Правый клик → Change hostname:

| Кто на схеме | Новое имя |
|--------------|-----------|
| левый host | `_dmiasnik-1_host` |
| левый router | `_dmiasnik-1_s` |
| правый router | `_dmiasnik-2_s` |
| правый host | `_dmiasnik-2_host` |

## E5. Три кабеля — медленно и по таблице

Включи **Add a link**. Каждый кабель — отдельная операция.

### Кабель 1: левый host → левый router

1. Кликни `_dmiasnik-1_host` → выбери **Ethernet0**.
2. Кликни `_dmiasnik-1_s` → выбери **Ethernet1** (не 0!).

### Кабель 2: между роутерами (underlay)

1. Кликни `_dmiasnik-1_s` → **Ethernet0**.
2. Кликни `_dmiasnik-2_s` → **Ethernet0**.

### Кабель 3: правый host → правый router

1. Кликни `_dmiasnik-2_host` → **Ethernet0**.
2. Кликни `_dmiasnik-2_s` → **Ethernet1**.

Esc — выйти из режима кабеля.

Проверь глазами:

- средний провод — только между двумя роутерами;
- боковые провода идут в **второй** порт роутера.

Если у роутера в меню нет Ethernet1 — шаблон собран с 1 adapter. Вернись в **Edit → Preferences → Docker containers → dmiasnik-router → Edit**, поставь Adapters = 4, **удали роутеры с холста**, перетащи заново, соедини снова.

## E6. Start и конфиги

1. **▶ Start all**.
2. Подожди, пока все 4 живые.
3. Открой консоль каждого устройства и выполни команды из файлов репозитория (**без** первой строки `#!/bin/sh`):

| Устройство | Файл открой в редакторе и копируй команды |
|------------|-------------------------------------------|
| `_dmiasnik-1_s` | `P2/_dmiasnik-1_s` |
| `_dmiasnik-2_s` | `P2/_dmiasnik-2_s` |
| `_dmiasnik-1_host` | `P2/_dmiasnik-1_host` |
| `_dmiasnik-2_host` | `P2/_dmiasnik-2_host` |

Как удобно работать:

1. На Ubuntu открой файл в текстовом редакторе / VS Code / `cat`.
2. Скопируй только строки с `ip`, `brctl`, `ip link`…
3. Вставь в консоль GNS3 (часто **Shift+Insert** или правый клик → Paste).

## E7. Проверки Part 2 static

На роутере:

```bash
ip addr show eth0
ip -d link show vxlan10
brctl show
```

Ожидание: есть `vxlan10`, в `br0` висят `vxlan10` и `eth1`.

На `_dmiasnik-1_host`:

```bash
ping -c 5 30.1.1.2
```

Должен пинговаться второй хост через VXLAN.

Во время ping на роутере:

```bash
tcpdump -i eth0 -n port 4789
```

Мелькают UDP-пакеты — туннель жив.

**Save.** Экспорт — раздел G.

### Multicast-вариант (кратко)

Либо снести VXLAN/bridge на тех же узлах и применить `P2/_dmiasnik-1_g` / `_dmiasnik-2_g`,  
либо сделать **отдельный** проект `P2-multicast` теми же кабелями и именами `_dmiasnik-1_g`, `_dmiasnik-2_g`.

Снос static перед multicast (на обоих роутерах):

```bash
ip link set eth1 down || true
ip link set br0 down || true
brctl delif br0 eth1 || true
brctl delif br0 vxlan10 || true
ip link del vxlan10 || true
brctl delbr br0 || true
```

# ЧАСТЬ F. Part 3 — опять те же клики

## F1. Картинка

```text
              _sshevche-1  (Route Reflector)
             /     |      \
            /      |       \
   _sshevche-2  _sshevche-3  _sshevche-4
         |           |            |
      host1       host2        host3
```

Все «коробки сверху» — шаблон **router**.  
Три снизу — шаблон **host**.

## F2. Новый проект

**File → New blank project** → Name `P3` → OK.

## F3. Натащить 7 устройств

1. Четыре раза перетащи `dmiasnik-router`.
2. Три раза перетащи `dmiasnik-host`.
3. Разложи как на картинке: RR сверху, три VTEP ниже, хосты под ними.

## F4. Переименовать

| Роль | Имя |
|------|-----|
| верхний центр | `_sshevche-1` |
| три средних | `_sshevche-2`, `_sshevche-3`, `_sshevche-4` |
| три нижних | `_sshevche-1_host`, `_sshevche-2_host`, `_sshevche-3_host` |

## F5. Шесть кабелей по таблице

Add a link. Не торопись. После каждого кабеля сверяйся с таблицей.

| От | Порт в меню GNS3 | К | Порт |
|----|------------------|----|------|
| `_sshevche-1` | Ethernet0 | `_sshevche-2` | Ethernet0 |
| `_sshevche-1` | Ethernet1 | `_sshevche-3` | Ethernet0 |
| `_sshevche-1` | Ethernet2 | `_sshevche-4` | Ethernet0 |
| `_sshevche-2` | Ethernet1 | `_sshevche-1_host` | Ethernet0 |
| `_sshevche-3` | Ethernet1 | `_sshevche-2_host` | Ethernet0 |
| `_sshevche-4` | Ethernet1 | `_sshevche-3_host` | Ethernet0 |

У `_sshevche-1` при соединении **обязаны** быть Ethernet0, Ethernet1, Ethernet2.  
Нет? → мало adapters в шаблоне.

## F6. Порядок включения — не нарушай

1. **Start** всех четырёх роутеров (хосты можно пока не трогать или Start, но IP на них — позже).
2. В консолях роутеров выполни конфиги из:
   - `P3/_sshevche-1`
   - `P3/_sshevche-2`
   - `P3/_sshevche-3`
   - `P3/_sshevche-4`
3. Подожди **15–30 секунд**.
4. На RR проверь:

```bash
vtysh -c "show ip ospf neighbor"
ping -c 2 1.1.1.2
ping -c 2 1.1.1.3
ping -c 2 1.1.1.4
vtysh -c "show bgp summary"
vtysh -c "show bgp l2vpn evpn route type multicast"
```

Ожидание: OSPF Full, BGP Established, есть Type 3.

5. Только потом на хостах выполни:
   - `P3/_sshevche-1_host`
   - `P3/_sshevche-2_host`
   - `P3/_sshevche-3_host`
6. Проверь Type 2 и ping:

```bash
vtysh -c "show bgp l2vpn evpn route type macip"
vtysh -c "show evpn mac vni 10"
```

С host1:

```bash
ping -c 5 20.1.1.2
ping -c 5 20.1.1.3
```

**Save.**

# ЧАСТЬ G. Экспорт для сдачи (portable project)

Subject хочет не скриншот, а файл `.gns3project`.

## G1. Что это

Это **ZIP-архив**: схема + (если включил галочку) Docker-образы.  
Его можно открыть на другом компьютере через Import.

## G2. Клик за кликом

1. Открой нужный проект (P1 / P2 / P3).
2. **File → Save**.
3. **File → Export portable project…**
4. В мастере найди галочки про образы. Названия бывают разные:
   - *Include base images*
   - *Include images*
   - *Export Docker images*
5. **Включи** их. Без этого файл «лёгкий», но на защите узлы могут не подняться.
6. Укажи имя файла:
   - `P1.gns3project`
   - `P2.gns3project`
   - `P3.gns3project`
7. Сохрани **внутрь** папки репозитория `P1/`, `P2/` или `P3/` рядом с текстовыми конфигами.
8. Дождись конца (с образами может идти **несколько минут**). Не убивай окно.

Проверка в терминале:

```bash
file P1/P1.gns3project
ls -lh P1/P1.gns3project
```

Должно быть `Zip archive`. Размер обычно заметный (не несколько килобайт).

Рядом в той же папке должны лежать текстовые конфиги устройств (`_dmiasnik-…`, `_sshevche-…`) — это отдельное требование задания.

## G3. Самопроверка импортом (по желанию)

На той же или другой машине с GNS3+Docker:

1. **File → Import portable project…**
2. Выбери `.gns3project`.
3. Дождись импорта.
4. Start all → открой консоль — убедись, что устройства оживают.

# ЧАСТЬ H. Как вставлять конфиги (три способа)

## H1. Руками в консоль GNS3 (лучший для защиты)

1. Start устройства.
2. Открой Console.
3. Скопируй команды из файла **без** `#!/bin/sh`.
4. Вставь в консоль.

Почему без `#!/bin/sh`: в уже открытом shell эта строка — не «заголовок файла», а попытка запустить команду и часто даёт ошибку / смущает.

## H2. Через docker cp

```bash
docker ps
docker cp P1/_dmiasnik-1_host <ID_КОНТЕЙНЕРА>:/tmp/setup.sh
docker exec -it <ID_КОНТЕЙНЕРА> sh /tmp/setup.sh
```

## H3. Важно про Stop

Кнопка **Stop** гасит контейнер. IP, VXLAN, bridge, которые ты настроил руками, **часто пропадают**.  
После нового Start конфиги нужно применить снова (если только export/import не сохранил состояние так, как ожидает твоя версия — не полагайся вслепую).

# ЧАСТЬ I. Боли новичков (сначала читай сюда, если что-то «не так»)

| Что видишь | Что делать |
|------------|------------|
| В New Docker image нет `dmiasnik-*` | Собрать образы (A4), закрыть GNS3 полностью, открыть снова |
| Can't connect to local server | Edit → Preferences → Local server; перезапуск GNS3; reboot VM |
| Слева нет наших иконок | Preferences → Docker containers — создать шаблоны; View → показать All devices |
| Console открылась и сразу закрылась | Start command в шаблоне должен быть **пустой**; `docker ps -a` — почему Exited |
| У роутера нет Ethernet1/2 | Edit шаблона → Adapters = 4; удалить узел с холста; перетащить новый |
| Ping в P1 не идёт | eth0 up на обоих? кабель Ethernet0↔Ethernet0? адреса 10.1.1.1 и .2/24? |
| Ping в P2 не идёт, VXLAN «есть» | Хост почти наверняка воткнут в Ethernet0 роутера вместо **Ethernet1** |
| После Stop всё «забылось» | Это нормально для эфемерных контейнеров — заново примени конфиг |
| Export весит мало | Забыл галочку Include images — экспортируй снова |
| Не понимаю, куда жать Add a link | Сначала клик по иконке кабеля, потом по первому устройству, выбрать порт, потом по второму, выбрать порт |
