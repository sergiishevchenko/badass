### Как работает GNS3

GNS3 — симулятор сети. На холсте расставляешь узлы (у нас это Docker-контейнеры), соединяешь их виртуальными кабелями и запускаешь.

- Каждый узел — настоящий Linux со своими интерфейсами `eth0`, `eth1`…
- Кабель в GNS3 — виртуальный линк между интерфейсами двух контейнеров.
- Проект сохраняется и экспортируется в `.gns3project` (ZIP), а на другой машине открывается через Import.

### Как работает BGP и зачем он нужен

BGP (RFC 4271) — протокол, которым роутеры обмениваются информацией о маршрутах. На нём работает весь интернет: автономные системы (сети провайдеров) объявляют друг другу, какие сети через них доступны. Соседи устанавливают TCP-сессию на порт 179 и передают только изменения.

Зачем он нужен:

- масштабируется на миллионы маршрутов;
- позволяет гибко управлять политиками;
- через расширение MP-BGP (RFC 4760) переносит не только IPv4, но и другие типы данных. В P3 так передаётся EVPN: MAC-адреса и VNI.

### Разница между L2 и L3

| | L2 (канальный) | L3 (сетевой) |
|---|---|---|
| Адрес | MAC, физический, вшит в карту | IP, логический, назначается |
| Устройство | свитч / мост | роутер |
| Область | один сегмент (широковещательный домен) | между сетями |
| Как ищется получатель | свитч учит MAC и пересылает кадр | роутер смотрит таблицу маршрутов |
| Единица данных | кадр (frame) | пакет (packet) |

Broadcast живёт только внутри L2-сегмента, роутер его дальше не пропускает.

## Part 1 — Theory

### Что такое программа маршрутизации (packet routing software)

Программа, которая превращает обычный Linux в роутер. Она обменивается маршрутами с соседями по протоколам (BGP, OSPF, IS-IS), вычисляет лучшие пути и записывает их в таблицу маршрутов ядра. Сами пакеты пересылает ядро, а программа только решает, куда. У нас это **FRRouting** (FRR), форк Quagga.

### Что такое `bgpd`

Демон FRR, реализующий BGP. Устанавливает сессии с соседями, принимает и объявляет маршруты. В P3 он переносит EVPN-маршруты Type 2 и Type 3.

### Что такое `ospfd`

Демон FRR, реализующий OSPFv2 (RFC 2328). Это протокол внутренней маршрутизации (IGP): роутеры обмениваются описанием своих линков, каждый строит карту сети и по алгоритму Дейкстры (SPF) считает кратчайшие пути. В P3 он делает loopback всех роутеров доступными друг другу (underlay).

### Что такое routing engine

Это **zebra**, ядро FRR. Она управляет интерфейсами, собирает маршруты от всех демонов (`bgpd`, `ospfd`, `isisd`), выбирает лучшие и через netlink записывает их в таблицу ядра Linux. Без zebra остальные демоны с ядром не работают.

В сабджекте также требуется `isisd` — ещё один IGP (IS-IS), альтернатива OSPF. Он запущен, но не настроен.

### Что такое BusyBox

Один маленький бинарник, внутри которого собраны сотни Unix-утилит (`sh`, `ls`, `ping`, `ip`, `vi`…). Даёт минимальную командную строку в лёгком контейнере. У нас образ хоста — Alpine с `busybox-extras`, плюс полные `iproute2`, `iputils` и `tcpdump`.

## Part 2 — Theory

### Что такое VXLAN и чем отличается от VLAN

VXLAN (RFC 7348) переносит L2-сеть через L3: Ethernet-кадр целиком упаковывается в UDP (порт 4789) с заголовком, где указан номер сегмента VNI.

| | VLAN | VXLAN |
|---|---|---|
| Как работает | метка 4 байта в кадре | кадр внутри UDP/IP |
| Номер | 12 бит, ~4094 | VNI 24 бита, ~16 млн |
| Через роутеры | нет | да, это обычный IP |

### Что такое свитч (switch)

L2-устройство: соединяет машины в один сегмент, запоминает, за каким портом какой MAC, и пересылает кадры только нужному порту. Broadcast и неизвестные адреса рассылает во все порты.

В нашей топологии отдельного свитча нет, его роль на каждом роутере выполняет мост `br0`. Если на схеме в сабджекте он нарисован отдельно, это то же самое: он объединяет порты в один L2-сегмент.

### Что такое мост (bridge)

Программный свитч внутри Linux. `br0` объединяет два порта роутера:

- `eth1` — к хосту;
- `vxlan10` — в туннель.

Кадр хоста из `eth1` попадает в туннель, и наоборот. `eth0` в мост не входит: это underlay, по нему едут UDP-пакеты.

### Разница broadcast и multicast

- **Broadcast** — всем в сегменте без исключения (`ff:ff:ff:ff:ff:ff`, например ARP).
- **Multicast** — только тем, кто подписался на группу (у нас `239.1.1.1`). Подписка идёт через IGMP, остальные этот трафик не получают.

### Как работает топология

Два хоста `30.1.1.1` и `30.1.1.2` подключены к разным роутерам, но находятся в одной сети `/24`. Роутеры соединены линком `10.1.1.0/24`. Кадр хоста идёт так:

```text
eth1 → br0 → vxlan10 (упаковка в UDP, VNI 10) → eth0 → второй роутер → распаковка → br0 → eth1 → хост
```

Хосты пингуют друг друга, как будто сидят в одном свитче.

## Part 2 — Practice — static

### Файлы конфигурации

`P2/_dmiasnik-1_s`, `P2/_dmiasnik-2_s` (роутеры) и `P2/_dmiasnik-1_host`, `P2/_dmiasnik-2_host` (хосты). Главная строка:

```bash
ip link add vxlan10 type vxlan id 10 remote 10.1.1.2 dstport 4789 dev eth0
```

Здесь `id 10` — это VNI 10, а `remote` — жёстко прописанный адрес соседа.

### Импорт, запуск, настройка

1. **File → Import portable project** → `P2/P2.gns3project`.
2. **Start all**.
3. `docker exec -it ID sh` на каждом узле, ввести команды из файлов.

Проверка:

```bash
ip -d link show vxlan10
brctl show
```

`ip -d link show vxlan10` показывает `id 10` и `remote`, а `brctl show` — что в `br0` входят `eth1` и `vxlan10`.

### Ping и обязательный захват пакетов

На роутере:

```bash
tcpdump -i eth0 -n port 4789
```

С хоста `30.1.1.1`:

```bash
ping 30.1.1.2
```

Ожидаемый вывод `tcpdump`:

```text
IP 10.1.1.1.xxxxx > 10.1.1.2.4789: VXLAN, flags [I] (0x08), vni 10
IP 30.1.1.1 > 30.1.1.2: ICMP echo request
```

Это и есть «результат, похожий на сабджект»: снаружи UDP между роутерами, внутри ICMP хостов, и видно `vni 10`.

## Part 2 — Practice — group

### Файлы конфигурации

`P2/_dmiasnik-1_g`, `P2/_dmiasnik-2_g`. Отличие от static ровно в одном параметре:

```bash
ip link add vxlan10 type vxlan id 10 group 239.1.1.1 dstport 4789 dev eth0
```

### Настройка и проверка

Как в static, плюс:

```bash
ip maddr show dev eth0
```

Команда показывает, что `eth0` подписан на `239.1.1.1`.

### Захват пакетов

Тот же `tcpdump -i eth0 -n port 4789`. Первый ARP (broadcast) уйдёт на `10.1.1.x > 239.1.1.1.4789`. Когда MAC-адреса выучены, ping идёт напрямую на адрес соседа.

### Разница со static и преимущества

- В static адрес соседа прописан руками (`remote`). Для каждого нового роутера придётся править конфиги всех остальных.
- В multicast адреса соседа нет вообще. Все VTEP подписываются на одну группу, BUM-трафик (broadcast, unknown unicast, multicast) уходит в группу, и его получают все участники.
- **Плюс:** соседи находятся автоматически. Новый роутер просто подписывается на группу, конфиг остальных не меняется. Это масштабируется.
- **Минус:** сеть должна поддерживать multicast.

## Part 3 — Theory

### Что такое BGP EVPN

EVPN (RFC 7432) — набор BGP-маршрутов, которые служат **control plane** для VXLAN. Вместо того чтобы изучать MAC-адреса флудом (как в P2), VTEP заранее объявляют друг другу через BGP:

- в каких VNI они участвуют;
- какие MAC-адреса за ними находятся.

Передаётся через MP-BGP, `address-family l2vpn evpn`.

### Принцип route reflection

По правилам iBGP маршрут, полученный от одного iBGP-соседа, не пересылается другим iBGP-соседям. Поэтому все роутеры пришлось бы соединять со всеми (full mesh, N·(N−1)/2 сессий).

**Route Reflector** снимает это ограничение: leaf соединяются только с RR (`_sshevche-1`), а RR пересылает (отражает) маршруты каждого leaf остальным. Это задаёт `route-reflector-client`. Новый leaf — одна новая сессия.

### Что такое VTEP

VXLAN Tunnel Endpoint — конец туннеля. Это роутер, который упаковывает кадры своих хостов в VXLAN и распаковывает чужие. У нас это leaf `_sshevche-2`, `_sshevche-3`, `_sshevche-4` с интерфейсом `vxlan10`. В качестве адреса туннеля используется loopback (`local 1.1.1.x`).

### Что такое VNI

VXLAN Network Identifier — номер виртуального L2-сегмента (24 бита). Одинаковый VNI означает одну сеть. У нас VNI 10: `ip link add vxlan10 type vxlan id 10`.

### Разница между Type 2 и Type 3

- **Type 3 (IMET, Inclusive Multicast Ethernet Tag):** «я VTEP `1.1.1.x`, участвую в VNI 10, BUM для этого VNI шлите мне». Появляется сразу при старте, **без хостов**. Из него строится список рассылки широковещательных кадров.
- **Type 2 (MAC/IP Advertisement):** «MAC такого-то хоста (и, если известен, IP) находится за мной». Появляется **только когда хост подключился** и отправил кадр.

### Как работает топология

1. **OSPF (underlay):** все loopback `1.1.1.1–4` доступны друг другу.
2. **BGP:** leaf поднимают iBGP-сессии к RR со своих loopback.
3. **Type 3:** каждый VTEP объявляет VNI 10.
4. **Type 2:** хост подключился, его leaf объявил MAC, RR разослал объявление остальным.
5. **Data plane:** кадр хоста упаковывается в VXLAN на loopback нужного VTEP и едет через RR как обычный IP.

Итог: хосты `20.1.1.1–3` пингуют друг друга.

## Part 3 — Practice

### Файлы конфигурации

- `P3/_sshevche-1` — RR: OSPF + BGP Route Reflector;
- `P3/_sshevche-2`, `_sshevche-3`, `_sshevche-4` — leaf: VXLAN + `br0` + OSPF + BGP с `advertise-all-vni`;
- `P3/_sshevche-N_host` — IP хостов.

### Импорт, запуск, настройка

1. **File → Import portable project** → `P3/P3.gns3project`.
2. **Start** только на четырёх роутерах.
3. На каждом роутере `docker exec -it ID sh` и ввести блок из файла (или `docker cp` + `sh /tmp/setup.sh`).

### Выключить все хосты

В GNS3 выделить три хоста → правый клик → **Stop** (или просто не запускать их).

### Только Type 3, без Type 2

На RR:

```bash
vtysh -c "show ip ospf neighbor"
vtysh -c "show bgp summary"
vtysh -c "show bgp l2vpn evpn route type multicast"
vtysh -c "show bgp l2vpn evpn route type macip"
```

- `show ip ospf neighbor` — три соседа в состоянии `Full`;
- `show bgp summary` — три сессии `Estab`;
- `show bgp l2vpn evpn route type multicast` — три маршрута `[3]`;
- `show bgp l2vpn evpn route type macip` — **пусто**.

### Обучение на VTEP: один хост без IP

1. Запустить **один** хост в GNS3, IP на нём **не** назначать.
2. Хост всё равно отправляет служебные кадры: при поднятии интерфейса Linux сам шлёт IPv6 neighbor discovery с link-local адреса. Мост leaf видит его MAC на `eth1`, zebra передаёт его в BGP, и появляется Type 2 (только MAC, без IP).
3. Проверить:

```bash
vtysh -c "show bgp l2vpn evpn route type macip"
vtysh -c "show evpn mac vni 10"
bridge fdb show dev vxlan10
```

- `show bgp l2vpn evpn route type macip` на RR — появился один `[2]` с MAC этого хоста;
- `show evpn mac vni 10` на leaf — MAC отмечен как local на своём leaf и как remote на остальных;
- `bridge fdb show dev vxlan10` на другом leaf — MAC с `dst 1.1.1.x`.

Если Type 2 не появился, можно внутри хоста выполнить `ip link set eth0 up`. Это не назначение IP, но интерфейс начнёт слать кадры.

### Включить все хосты и назначить IP

Start на остальных. На каждом хосте:

```bash
ip addr add 20.1.1.N/24 dev eth0
ip link set eth0 up
```

На RR видно три Type 2.

### Ping и захват пакетов

На leaf `_sshevche-2`:

```bash
tcpdump -i eth0 -n port 4789
```

С хоста `20.1.1.1`:

```bash
ping 20.1.1.3
```

Ожидаемый вывод:

```text
IP 1.1.1.2.xxxxx > 1.1.1.4.4789: VXLAN, flags [I] (0x08), vni 10
IP 20.1.1.1 > 20.1.1.3: ICMP echo request
```

Внешние адреса здесь — loopback VTEP, внутри ICMP хостов, `vni 10`.

### VXLAN ID = 10

```bash
ip -d link show vxlan10
vtysh -c "show evpn vni"
```

Первая показывает `id 10`, вторая — VNI 10.

### Видны пакеты OSPF

На любом роутере:

```bash
tcpdump -i eth0 -n proto ospf
```

Каждые ~10 секунд идут строки `OSPFv2, Hello` от `10.1.1.x` к `224.0.0.5` (multicast-адрес всех OSPF-роутеров).
