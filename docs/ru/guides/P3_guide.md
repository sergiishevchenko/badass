# Part 3 — BGP EVPN

## Что строим

Мини-дата-центр из 7 устройств: один центральный роутер, три роутера с хостами и три хоста.

Хосты стоят за разными роутерами, но должны работать как в одной локалке и пинговать друг друга. В Part 2 роутеру прописывали соседа руками (`remote`) или группу (`group`). Здесь роутеры сами узнают, кто участвует в сети и за каким роутером сидит какой хост.

```text
                 sshevche-1   (RR)
                 lo 1.1.1.1
          eth0 /     | eth1    \ eth2
              /      |          \
     sshevche-2   sshevche-3   sshevche-4   (VTEP)
     lo 1.1.1.2   lo 1.1.1.3   lo 1.1.1.4
          | eth1       | eth1        | eth1
          |            |             |
   sshevche-1-host  sshevche-2-host  sshevche-3-host
     20.1.1.1         20.1.1.2         20.1.1.3
```

- **RR** (Route Reflector) — верхний роутер `sshevche-1`. Хостов у него нет. Он связывает остальные роутеры и пересылает им друг про друга сведения.
- **VTEP** — три средних роутера. У каждого свой хост и свой конец туннеля VXLAN.
- **Хосты** — обычные компьютеры, все в сети `20.1.1.0/24`.

Имена выше — подписи узлов в GNS3. Конфиги лежат в `P3/_sshevche-1`, `P3/_sshevche-1_host` и так далее.

---

## Три слоя

Всё держится на трёх вещах, каждая поверх предыдущей:

| Слой | Что делает | Чем сделано |
|------|------------|-------------|
| Underlay | роутеры достают друг до друга по IP | OSPF |
| Control plane | роутеры рассказывают друг другу про VNI и MAC хостов | BGP EVPN через RR |
| Data plane | кадры хостов едут между роутерами | VXLAN, VNI 10 |

Если не работает нижний слой, не работает и всё, что выше. Поэтому включаются и проверяются они строго по порядку.

---

## 1. OSPF — роутеры видят друг друга

Каждый роутер объявляет соседям свои сети, и все узнают маршруты до всех. Главное — маршруты до loopback `1.1.1.x`: по ним дальше работают BGP и VXLAN.

**Loopback** — виртуальный интерфейс `lo` роутера. Он не привязан к кабелю и не падает вместе с портом. Его адрес служит постоянным «именем» роутера.

Адреса underlay:

| Линк | Сеть | RR | VTEP |
|------|------|----|------|
| RR — sshevche-2 | `10.1.1.0/30` | `10.1.1.1` на eth0 | `10.1.1.2` на eth0 |
| RR — sshevche-3 | `10.1.1.4/30` | `10.1.1.5` на eth1 | `10.1.1.6` на eth0 |
| RR — sshevche-4 | `10.1.1.8/30` | `10.1.1.9` на eth2 | `10.1.1.10` на eth0 |

`/30` — сеть ровно на два адреса: по одному на каждый конец кабеля.

Все роутеры в одной зоне OSPF, `area 0`. Когда соседи договорились, их состояние — `Full`.

Подробнее: [`../OSPFD_ISIS.md`](../OSPFD_ISIS.md).

## 2. BGP EVPN — роутеры рассказывают про хостов

BGP поднимается между loopback роутеров, поэтому без OSPF не стартует. Все роутеры в одной AS `65000`, это внутренний BGP (iBGP).

### Зачем RR

По правилам iBGP роутер не передаёт дальше то, что узнал от другого iBGP-соседа. Без RR каждому роутеру пришлось бы держать сессию с каждым: на 4 роутера это 6 сессий, на 10 — уже 45.

С RR каждый VTEP держит одну сессию: только с `sshevche-1`. RR получает сведения от одного VTEP и отражает их двум другим.

```text
           RR
         / | \
   VTEP2 VTEP3 VTEP4      3 сессии вместо 6
```

### Что передаётся

Обычный BGP возит IP-маршруты. Для MAC-адресов в нём есть отдельный канал — address family `l2vpn evpn`. Именно его включают на всех сессиях.

По этому каналу ходят два типа сведений:

| Тип | Что значит | Когда появляется |
|-----|------------|------------------|
| **Type 3** | «я, VTEP `1.1.1.x`, участвую в VNI 10, шлите мне broadcast» | сразу, как поднялись BGP-сессии, хосты ещё не нужны |
| **Type 2** | «MAC такого-то хоста сидит за мной, VTEP `1.1.1.x`» | когда от хоста на порт VTEP пришёл первый кадр |

Type 3 даёт каждому VTEP список остальных. По нему рассылается broadcast, например ARP «кто владеет 20.1.1.3?»: копия уходит каждому VTEP из списка.

Type 2 говорит, куда слать кадр конкретному хосту. Дальше кадр идёт сразу нужному VTEP, а не всем.

Подробнее: [`../BGP.md`](../BGP.md), [`../BGP_EVPN.md`](../BGP_EVPN.md).

## 3. VXLAN — кадры хостов едут по туннелю

Туннель тот же, что в Part 2: VNI 10, UDP 4789, хост в мосту `br0` вместе с `vxlan10`. Отличается одна строка:

```bash
ip link add vxlan10 type vxlan id 10 dstport 4789 local 1.1.1.2 nolearning
```

- Нет `remote` и `group`. Кому слать, VTEP узнаёт из Type 3 и Type 2.
- `local 1.1.1.2` — внешний адрес пакетов. Это loopback, а не адрес кабеля.
- `nolearning` — не учить MAC из самого туннеля. Их приносит BGP. Два источника сведений мешали бы друг другу.

Подробнее: [`../VXLAN.md`](../VXLAN.md), [`../OVERLAY_UNDERLAY.md`](../OVERLAY_UNDERLAY.md).

## Как это включается по порядку

1. **OSPF.** Конфиги роутеров применены, через 10–30 секунд соседи в `Full`, loopback `1.1.1.x` пингуются.
2. **BGP.** Сессии VTEP с RR поднялись, у RR три соседа в `Estab`.
3. **Type 3.** Каждый VTEP объявил участие в VNI 10. Хосты ещё выключены, Type 2 нет — это правильно.
4. **Хосты.** Включили хосты, дали им адреса. VTEP увидели их MAC и объявили Type 2. RR разослал их остальным.
5. **Ping.** Хост `20.1.1.1` пингует `20.1.1.2` и `20.1.1.3`.

Путь ping от `20.1.1.1` до `20.1.1.3`:

```text
хост 20.1.1.1 → sshevche-2 ══ sshevche-1 ══ sshevche-4 → хост 20.1.1.3
                заворачивает   пересылает    разворачивает
                в UDP          как обычный   кадр
                от 1.1.1.2     IP-пакет      к 1.1.1.4
```

RR стоит на пути, но для него это просто UDP-пакет между двумя loopback. Про хостов он не знает.

## Конфиг роутеров

Каждый файл роутера делает три вещи: адреса, туннель (только на VTEP) и FRR через `vtysh`.

### RR — `P3/_sshevche-1`

Адреса на трёх кабелях и loopback:

```bash
ip addr add 10.1.1.1/30 dev eth0
ip addr add 10.1.1.5/30 dev eth1
ip addr add 10.1.1.9/30 dev eth2
ip addr add 1.1.1.1/32 dev lo
```

OSPF — объявить три линка и свой loopback:

```text
router ospf
 network 10.1.1.0/30 area 0
 network 10.1.1.4/30 area 0
 network 10.1.1.8/30 area 0
 network 1.1.1.1/32 area 0
```

BGP — три соседа, у всех EVPN, все клиенты RR:

```text
router bgp 65000
 bgp router-id 1.1.1.1
 no bgp default ipv4-unicast
 neighbor 1.1.1.2 remote-as 65000
 neighbor 1.1.1.2 update-source lo
 address-family l2vpn evpn
  neighbor 1.1.1.2 activate
  neighbor 1.1.1.2 route-reflector-client
```

Для `1.1.1.3` и `1.1.1.4` те же строки.

### VTEP — `P3/_sshevche-2`

Адрес на кабеле к RR и loopback. `eth1` к хосту поднимается без адреса:

```bash
ip addr add 10.1.1.2/30 dev eth0
ip addr add 1.1.1.2/32 dev lo
```

Туннель и мост — как в разделе про VXLAN.

OSPF — свой линк и свой loopback:

```text
router ospf
 network 10.1.1.0/30 area 0
 network 1.1.1.2/32 area 0
```

BGP — один сосед, RR:

```text
router bgp 65000
 bgp router-id 1.1.1.2
 no bgp default ipv4-unicast
 neighbor 1.1.1.1 remote-as 65000
 neighbor 1.1.1.1 update-source lo
 address-family l2vpn evpn
  neighbor 1.1.1.1 activate
  advertise-all-vni
```

`sshevche-3` и `sshevche-4` такие же, со своими адресами: `10.1.1.6` и `1.1.1.3`, `10.1.1.10` и `1.1.1.4`.

### Что значат строки FRR

| Строка | Смысл |
|--------|-------|
| `network ... area 0` | включить OSPF на этой сети и объявить её соседям |
| `router bgp 65000` | BGP в AS 65000, у всех роутеров одна AS |
| `bgp router-id 1.1.1.x` | идентификатор роутера, взят его loopback |
| `no bgp default ipv4-unicast` | не включать обычные IPv4-маршруты: BGP нужен только для EVPN |
| `neighbor ... remote-as 65000` | сосед в той же AS |
| `neighbor ... update-source lo` | ходить к соседу со своего loopback, а не с адреса кабеля |
| `address-family l2vpn evpn` + `activate` | включить с этим соседом обмен EVPN |
| `route-reflector-client` | только на RR: отражать сведения этого соседа остальным |
| `advertise-all-vni` | только на VTEP: объявить свои VNI, отсюда Type 3 и Type 2 |

У RR есть `route-reflector-client`, но нет `advertise-all-vni`: туннеля у него нет. У VTEP наоборот.

### Хосты

Только адрес, как в Part 2:

```bash
ip addr add 20.1.1.1/24 dev eth0
ip link set eth0 up
```

`20.1.1.2` и `20.1.1.3` на двух других.

## Проверка

Все команды — в shell верхнего роутера `sshevche-1`, кроме ping хостов.

| Команда | Что должно быть |
|---------|-----------------|
| `vtysh -c "show ip ospf neighbor"` | три соседа `1.1.1.2`, `1.1.1.3`, `1.1.1.4` в `Full` |
| `ping -c 2 1.1.1.2` (и `.3`, `.4`) | ответы, `0% packet loss` |
| `vtysh -c "show bgp summary"` | три соседа в `Estab` |
| `vtysh -c "show bgp l2vpn evpn route type multicast"` | Type 3 от каждого VTEP, ещё до хостов |
| `vtysh -c "show bgp l2vpn evpn route type macip"` | после включения хостов — Type 2 с их MAC |
| `ping 20.1.1.2`, `ping 20.1.1.3` на хосте `20.1.1.1` | ответы |

Пошаговый порядок на защите — в [`EVAL.md`](EVAL.md).
