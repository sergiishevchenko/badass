# Что такое zebra и Quagga

## Простыми словами

**zebra** и **Quagga** — это не два разных протокола вроде OSPF или BGP. Это **программы для Linux**, которые превращают обычный сервер/контейнер в программный маршрутизатор.

- **Zebra** — исторически первый большой открытый проект такой «софт-роутер» для Unix/Linux (GNU Zebra). Ещё **zebra** — имя **центрального демона** в семействе: он один говорит с ядром Linux и держит таблицу маршрутов.
- **Quagga** — форк (продолжение ветки) того же мира после Zebra. Долгое время именно Quagga ставили на Linux-роутеры в лабах и на проде.
- **FRRouting (FRR)** — уже современный форк Quagga. В проекте стоит **FRR**. Имена zebra и quagga относятся к тому же семейству: те же идеи, те же демоны (`zebra`, `bgpd`, `ospfd`…).

Роль программного маршрутизатора закрывает образ `frrouting/frr`: внутри демон **zebra** и протоколы поверх него.

---

## Зачем это нужно

Ядро Linux *умеет* маршрутизировать IP (включил forwarding — пакеты ходят между интерфейсами). Но ядро само:

- не говорит OSPF с соседями;
- не поднимает BGP-сессии;
- не раздаёт EVPN Type 2/3.

Человек мог бы всё прописать руками (`ip route add …`). На нескольких роутерах и при живой топологии это ад. Нужна **control plane** — демоны, которые:

1. общаются с соседями по протоколу (OSPF Hello, BGP UPDATE);
2. решают, какой маршрут лучше;
3. просят ядро: «добавь/удали маршрут в таблице».

Именно это делают Zebra / Quagga / FRR.

---

## История одной строкой

```text
GNU Zebra  →  Quagga  →  FRRouting (FRR)
   1990-е       2000-е         сейчас
```

- **GNU Zebra** — первоисточник. Многие до сих пор говорят «zebra» в быту про весь софт.
- **Quagga** — форк: активнее развивали BGP/OSPF и т.д., когда Zebra затормозил.
- **FRRouting** — форк Quagga от сообщества (Linux Foundation и др.). Сегодня это де-факто стандарт. Пакет/образ `frrouting/frr`, CLI `vtysh`, файл `/etc/frr/daemons`.

В документации «zebra» может значить и старый проект, и демон `zebra` внутри Quagga/FRR. На защите лучше уточнять: «у нас FRR, демон zebra обязателен».

## Архитектура: один zebra, много протокольных демонов

Идея с 90-х не менялась:

```text
  bgpd     ospfd     isisd     ripd ...
     \       |        /
      \      |       /
         zebra
           |
     ядро Linux (FIB / маршруты, интерфейсы)
```

### Демон `zebra`

Центральный процесс:

- следит за интерфейсами (`eth0` up/down, адреса);
- принимает маршруты от `bgpd`, `ospfd`, …;
- ставит лучшие в **kernel routing table**;
- раздаёт протокольным демонам информацию об интерфейсах и маршрутах.

Без `zebra` остальные демоны «в воздухе»: им некуда отдавать маршруты в систему.

В нашем `P1/daemons`:

```text
zebra=yes
bgpd=yes
ospfd=yes
isisd=yes
```

### Демоны протоколов

| Демон | Протокол | В BADASS |
|-------|----------|----------|
| `bgpd` | BGP (+ EVPN через MP-BGP) | Part 3 |
| `ospfd` | OSPFv2 | Part 3 underlay |
| `isisd` | IS-IS | запущен, маршруты через него не строятся |
| `ripd` / др. | RIP и прочее | выключены |

Каждый демон — **отдельный процесс**. Упал `bgpd` — OSPF может жить. Упал `zebra` — маршрутизация через FRR разваливается.

### `vtysh`

Единая консоль «как Cisco»: один CLI на все демоны. Пишешь `router ospf` / `router bgp` — vtysh раскидывает по нужным процессам. Без vtysh пришлось бы конфигурировать каждый демон своим сокетом.

## Zebra (проект) vs демон zebra vs Quagga vs FRR

| Название | Что это |
|----------|---------|
| **GNU Zebra** | Старый проект-роутер целиком |
| **демон zebra** | Процесс-ядро в Quagga/FRR |
| **Quagga** | Форк Zebra, долго был «тем самым» пакетом `quagga` в Debian |
| **FRRouting** | Современный форк Quagga; то, что мы используем |

Пакет с именем `quagga` не обязателен. Нужно ПО с той же ролью: демоны маршрутизации и включённые BGPD, OSPFD, IS-IS. FRR закрывает это в текущих версиях.

---

## Quagga подробнее

Quagga (название — вид зебры «quagga», вымершая) унаследовала:

- модульную схему «zebra + протоколы»;
- конфиги в духе Cisco;
- `vtysh`.

Ставилась как `apt install quagga`. Сейчас во многих дистрибутивах Quagga **устарела/убрана**, рекомендуют FRR. В учебных PDF 42 до сих пор пишут Quagga — по привычке и по RFC-эпохе лаб.

Если кто-то на защите спросит «почему не Quagga?»: «Quagga — предок; FRR — актуальный форк с тем же zebra/bgpd/ospfd/isisd».

## FRR — что у нас в Docker

Образ:

```dockerfile
FROM frrouting/frr:latest
```

При старте `/usr/lib/frr/docker-start` читает `/etc/frr/daemons` и поднимает отмеченные процессы. Мы копируем свой `daemons`, чтобы **zebra, bgpd, ospfd, isisd = yes**.

Проверка в контейнере:

```bash
ps aux | grep -E "zebra|bgpd|ospfd|isisd"
vtysh -c "show version"
vtysh -c "show interface brief"
```

`show version` обычно пишет **FRRouting** — это нормально. Демон `zebra` в списке процессов всё равно должен быть.
