# Что такое VXLAN

VXLAN (Virtual Extensible LAN, RFC 7348) переносит обычную локальную сеть через IP-сеть роутеров.

Два компьютера, между которыми стоят роутеры, ведут себя так, будто воткнуты в один свитч. Они видят MAC-адреса друг друга, шлют ARP и широковещательные кадры. По дороге их кадры лежат внутри UDP-пакетов.

В проекте это сеть с номером **VNI 10**. В Part 2 её собирают руками. В Part 3 ту же сеть возит VXLAN, а список соседей и MAC-адресов раздаёт BGP EVPN.

---

## Зачем она нужна

Обычный свитч соединяет машины одним кабельным сегментом. Как только между ними появляется маршрутизатор, этот сегмент кончается: широковещание и ARP дальше не проходят.

В дата-центре серверы стоят в разных стойках. Между стойками уже есть IP-сеть. Приложению при этом нужна одна локалка: одни MAC-адреса, один broadcast. Тянуть весь дата-центр одним огромным свитчем нельзя, он разваливается от штормов и петель.

VXLAN оставляет IP-сеть как транспорт и поверх неё строит виртуальный свитч. VLAN для этого тесен: у него 4096 номеров. У VXLAN номер сегмента занимает 24 бита, сегментов около 16 миллионов.

---

## Что происходит с кадром

Хост отправляет обычный Ethernet-кадр: MAC отправителя, MAC получателя, внутри IP и, например, ICMP.

Роутер на своём конце туннеля этот кадр не переписывает. Он кладёт его целиком в новый пакет:

```text
внешний Ethernet и внешний IP роутеров
UDP, порт назначения 4789
заголовок VXLAN с номером VNI
исходный кадр хоста, как был
```

Дальше пакет идёт по обычной IP-сети до второго роутера. Тот снимает оболочку и отдаёт исходный кадр своему хосту. Хост видит кадр соседа, а не UDP.

Порт **4789** — стандартный порт VXLAN. На линии между роутерами `tcpdump` показывает UDP 4789. ICMP хоста спрятан внутри.

---

## Слова, которые встречаются в проекте

**VNI** — номер виртуального свитча. Одинаковый номер означает одну локалку. Разный номер означает разные локалки: хосты друг друга не видят, даже если туннели идут по одним и тем же роутерам.

У нас везде VNI **10**. Интерфейс в Linux называется `vxlan10`. Имя можно было выбрать другое. Число `id 10` в команде — это и есть номер сегмента.

**VTEP** — конец туннеля. У нас это роутер с интерфейсом `vxlan10`. Он заворачивает кадры своего хоста и разворачивает чужие. Сам хост — обычный компьютер с одним `eth0`, он про туннель не знает.

**Underlay** — сеть роутеров, по которой едут внешние UDP-пакеты.

- Part 2: адреса `10.1.1.1` и `10.1.1.2` на `eth0` между двумя роутерами.
- Part 3: линки `/30` и loopback `1.1.1.x`, маршруты между ними строит OSPF.

Underlay возит пакеты роутеров. MAC-адреса хостов ему не нужны.

**Overlay** — сама виртуальная локалка VNI 10, то, что видят хосты.

- Part 2: хосты `30.1.1.1` и `30.1.1.2`.
- Part 3: хосты `20.1.1.1`, `20.1.1.2`, `20.1.1.3`.

Для хоста сосед находится в той же сети `/24`. Про OSPF между роутерами он не знает.

**Bridge `br0`** склеивает порт хоста и туннель в один свитч. Интерфейс `vxlan10` — это вход в туннель. Хост подключён к `eth1`. Пока их не объединить, кадр хоста в туннель не попадёт:

```text
хост --- eth1 ---+
                 +--- br0
туннель vxlan10 -+
```

`eth0` роутера занят underlay, кабелем к соседнему роутеру. Хост сидит на `eth1`. Если воткнуть хост в `eth0`, мост и туннель есть, а ping между хостами нет.

## Как VXLAN включён в Part 2

Схема одна и та же:

```text
хост --- роутер ======== роутер --- хост
     eth1      eth0    eth0      eth1
```

Между роутерами кабель `eth0–eth0`. Каждый хост воткнут в `eth1` своего роутера. На обоих роутерах `vxlan10` и `eth1` собраны в `br0`.

Дальше два способа сказать туннелю, куда слать кадры, для которых ещё неизвестен конкретный получатель. Такие кадры называют BUM: broadcast (ARP, «кто владеет этим IP»), unknown unicast (MAC ещё не выучен) и multicast.

### Static

Каждый роутер знает IP соседа заранее:

```bash
ip link add vxlan10 type vxlan id 10 remote 10.1.1.2 dstport 4789 dev eth0
```

`remote 10.1.1.2` — весь BUM уходит на этот адрес. На втором роутере в `remote` стоит `10.1.1.1`. Для двух роутеров этого хватает. На каждом новом роутере соседа пришлось бы прописывать руками.

В `ip -d link show vxlan10` видны `id 10`, `remote` соседа и `dstport 4789`.

### Multicast

Адреса соседа в команде нет. Оба роутера вступают в одну группу:

```bash
ip link add vxlan10 type vxlan id 10 group 239.1.1.1 dstport 4789 dev eth0
```

BUM уходит на `239.1.1.1`. Его получают все, кто в этой группе. Нового роутера достаточно подписать на ту же группу.

В `ip -d link show vxlan10` видна `group 239.1.1.1`. В `ip maddr show dev eth0` та же группа на `eth0`.

Когда MAC получателя уже известен, кадр идёт ему напрямую, а не всей группе.

Проверка в обоих режимах одна: с хоста `30.1.1.1` проходит `ping 30.1.1.2`. На `eth0` роутера в это время `tcpdump -i eth0 -n port 4789` показывает UDP.

## Как VXLAN включён в Part 3

Туннель тот же: VNI 10, UDP 4789, хост по-прежнему в `br0` вместе с `vxlan10`. Меняется только то, кто говорит роутеру список соседей и MAC-адресов.

Команда на VTEP больше не содержит `remote` и `group`:

```bash
ip link add vxlan10 type vxlan id 10 dstport 4789 local 1.1.1.2 nolearning
```

`local 1.1.1.2` — внешний адрес источника. Это loopback роутера, он не зависит от того, через какой физический порт ушёл пакет.

`nolearning` выключает самообучение MAC из туннеля. Адреса приходят по BGP:

- Type 3 говорит, каким VTEP рассылать BUM;
- Type 2 говорит, за каким VTEP сидит конкретный MAC хоста.

Хосты `20.1.1.1`, `20.1.1.2` и `20.1.1.3` пингуют друг друга через этот туннель. На линии между роутерами по-прежнему виден UDP 4789.

---

## Если хосты не пингуются

Сначала underlay: с одного роутера Part 2 должен открываться `ping 10.1.1.2`. В Part 3 должны открываться loopback соседей `1.1.1.x`.

Потом туннель и мост: `ip -d link show vxlan10` показывает VNI 10 и порт 4789, `brctl show` показывает `br0` с портами `vxlan10` и `eth1`.

Хост при этом смотрит в `eth1` роутера. `eth0` — кабель к другому роутеру.
