# Что такое busybox

## Простыми словами

**busybox** — это один маленький исполняемый файл, внутри которого спрятаны десятки (а часто сотни) обычных Unix-команд: `ls`, `cat`, `cp`, `sh`, `ping`, `ifconfig` и многое другое.

Вместо того чтобы ставить отдельно пакет `coreutils`, отдельно `grep`, отдельно `ping`, в минимальной системе кладут один бинарник busybox. Вызываешь `ls` — на самом деле запускается busybox, который смотрит, *под каким именем* его вызвали, и ведёт себя как `ls`.

Аналогия: швейцарский нож. Один предмет, много инструментов. Не такой мощный, как полный набор отдельных утилит GNU, зато крошечный и достаточный для контейнера или встроенной системы.

---

## Зачем он вообще появился

Классический Linux на ноутбуке тянет за собой:

- GNU coreutils (`ls`, `cp`, `mv`…);
- util-linux;
- iputils;
- кучу зависимостей.

Это нормально для сервера на 20 ГБ. Плохо для:

- роутера с 8 МБ flash;
- initramfs при загрузке;
- Docker-образа, который хочется уложить в несколько мегабайт.

BusyBox родился именно под **embedded** (встраиваемые) системы. Позже его полюбили минимальные дистрибутивы вроде **Alpine Linux** и авторы маленьких контейнеров.

---

## Как это устроено технически

Один файл, например `/bin/busybox`. Рядом с ним (или вместо отдельных программ) стоят **симлинки** или **hardlink** с именами команд:

```text
/bin/ls  →  busybox
/bin/cat →  busybox
/bin/sh  →  busybox   (часто ash)
```

Когда ядро запускает `/bin/ls`, программа получает в `argv[0]` строку `ls`. Busybox читает это имя и переключается на нужную встроенную утилиту (applet).

Посмотреть, что умеет конкретная сборка:

```bash
busybox
busybox --help
busybox --list
```

`--list` печатает имена всех вкомпиленных applet. Набор **не фиксирован**: при сборке busybox из исходников выбирают, какие команды включить. Поэтому «busybox на Alpine» и «busybox на древнем роутере» — разные меню.

## Busybox vs «нормальные» GNU-утилиты

| | Busybox | GNU coreutils / полные пакеты |
|--|---------|-------------------------------|
| Размер | очень маленький | заметно больше |
| Опции команд | часто урезанный набор флагов | почти всё, что описано в man |
| Цель | embedded, контейнеры, recovery | десктоп и серверы |
| Shell | обычно `ash` (не bash) | часто bash |

Практически: `ls -l` работает, а какой-нибудь редкий флаг `ls --hyperlink` может отсутствовать. Для лабы (`ip`, `ping`, `sh`, базовый shell) busybox-уровня хватает. Поэтому в Dockerfile мы всё равно добавляем `iproute2`, `iputils`, `tcpdump` — там, где нужны «взрослые» утилиты, а не урезанный applet.

## Busybox и Alpine Linux

**Alpine** по умолчанию опирается на busybox:

- нет огромного bash из коробки — часто `/bin/sh` это ash из busybox;
- базовые команды уже «есть», потому что это и есть busybox;
- пакетный менеджер `apk` ставит допы отдельно.

Именно поэтому Part 1 начинается с `FROM alpine:latest` для host-образа: маленький образ + busybox из коробки.

Пакет **`busybox-extras`** в Alpine — это *расширение*: дополнительные applet (telnet и др.), которых нет в самом базовом наборе. В наших Dockerfile он ставится явно, чтобы требование subject было закрыто с запасом.

Роутерный образ `frrouting/frr` тоже на Alpine-подобной базе: busybox там тоже ожидаем, плюс мы снова ставим `busybox-extras`.

## Где busybox в проекте

### Требование (Part 1)

Первый образ: система на выбор + **как минимум busybox или эквивалент**.  
Второй образ: zebra/quagga (у нас FRR), bgpd, ospfd, IS-IS, и снова **busybox или эквивалент**.

### Как показать

Внутри контейнера host или router:

```bash
busybox
busybox --list | head
ls -l /bin/sh
which busybox
```

Если `sh` указывает на busybox — это как раз «эквивалентная среда на busybox».

### Чего busybox сам по себе не даёт

- FRRouting (`vtysh`, zebra, bgpd) — это не busybox.
- Нормальный `ip` из iproute2 — мы ставим отдельно (хотя у busybox есть урезанный `ip` applet, для VXLAN/bridge лучше полноценный iproute2).
- `brctl`, `tcpdump` — отдельные пакеты в нашем router Dockerfile.

Busybox — фундамент «это Linux-командная строка в маленьком бинарнике», а не весь сетевой стек проекта.

## Полезные команды busybox в лабе

Часто вызывают не `busybox ping`, а просто `ping`, если симлинк есть. Но можно и так:

```bash
busybox ping -c 3 10.1.1.2
busybox ifconfig
busybox route
busybox ash
```

В Alpine привычнее:

```bash
ping -c 3 10.1.1.2
ip addr
sh
```

за кулисами часть из этого всё равно может быть busybox; `ip` у нас обычно из пакета `iproute2`.

---

## Коротко

Busybox — один компактный бинарник с кучей базовых Unix-команд (Swiss Army knife для маленьких Linux). Задание требует его (или эквивалент) в host- и router-образах. Мы берём Alpine / FRR на Alpine, ставим `busybox-extras`, а сетевые вещи уровня VXLAN и FRR добавляем отдельными пакетами поверх этого минимума.
